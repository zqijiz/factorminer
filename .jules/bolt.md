## 2024-06-22 - [Performance Pattern: Pre-computing Rolling Window Operations in O(T) Loops]
**Learning:** In sequential time series algorithms (like KAMA) where element t depends on element t-1, we can't fully vectorize the time loop. However, performing sliding window aggregations (e.g. rolling sum of volatility) inside the loop causes operations to scale O(T * window), significantly slowing down execution.
**Action:** When forced to use a sequential time loop, always push aggregations outside the loop. Use `np.lib.stride_tricks.sliding_window_view(...).sum(...)` in NumPy or `.unfold(dim, window, step).sum(...)` in PyTorch to pre-calculate all rolling windows in a single vectorized step. This makes the inner loop O(T) instead of O(T * window), achieving substantial speedups for larger window sizes (e.g. >2x speedup for KAMA with window=10).
