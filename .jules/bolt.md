## 2025-02-28 - Fast Rolling Aggregations and Sequential Loop Assignments in Time Series
**Learning:** In sequential time series algorithms (like KAMA) where element t depends on element t-1, we can't fully vectorize the time loop. However, replacing boolean slice indexing assignments (`out[valid, t] = ...`) inside the loop with branchless `np.where`/`torch.where` avoids creating expensive intermediate arrays and speeds up the tight loop significantly. Furthermore, calculating rolling window aggregations inside the loop (`vol = np.nansum(np.abs(np.diff(x[:, t - window:t + 1], axis=1)), axis=1)`) is highly inefficient and creates severe overhead.
**Action:** When forced to use a time loop for sequential algorithms, always pull rolling aggregations out of the loop and pre-calculate them using `cumsum` (e.g., `cum_vol = np.cumsum(np.abs(np.diff(x)))`, padding with leading zero, and then doing O(1) lookups `cum_vol[:, t] - cum_vol[:, t - window]`). Additionally, inside sequential loops, always replace boolean slice assignments with branchless `np.where(valid, ..., out[:, t])` (or `torch.where(...)` to avoid host-device sync overhead).
